# Behaviour-Driven Specification (BDD): Agent-Managed FCC Soft Sensors & Decision Cockpit

> **Companion documents:** [Demo case](BCC.md) · [Features](features.md) · [SDD](SDD.md) · [Build guide](build.md) · [Checklist](checklist.md) · [Problem statement](fcc_soft_sensor_problem_statement.md) · [Solution design](fcc_ai_driven_soft_sensor_solutions.md)
>
> **Purpose:** turn the design into **testable behaviours** written in Gherkin (Given / When / Then). Each scenario is an acceptance criterion, automated with `pytest-bdd` (back end) and Playwright (cockpit). **All `@demo` scenarios run on the simulated data** in `sim_octave/data/<batch>/` (BigQuery `fcc_sim_minute`).

---

## 1. Summary

**The system must behave safely first, honestly second, and accurately third, and the cockpit must make all three visible to a decision-maker.**

1. **Safety:** no AI component or cockpit button writes to the DCS/MPC. Every recommendation needs human acceptance, which is recorded only.
2. **Honesty:**
   - Every estimate carries a probability distribution from several model families (Hybrid delta, PINN, GPR, Bayesian ridge) and a calibrated trust level.
   - **When the distribution is too wide, or the models disagree, no recommendation is issued** and the user is told why (BDD-15).
3. **Accuracy:** RMSE <= 1.5R (time-blocked) and <= 2.0R (leave-one-regime-out) on simulated data; 1-1.5x R on site, and 90% intervals that cover 85–95% of the truth.

Tags:

| Tag | Meaning |
|---|---|
| `@D1` `@D2` `@D3` | Decision supported: hydrotreater severity / cut points / trust |
| `@demo` | Runs today on simulated data (a simulated batch, run and minute are named in the scenario or step) |
| `@phase0` … `@phase4` | Site delivery phase (BCC §8) |
| `@safety` | Must pass before any deployment |
| `@gpr` `@pinn` `@hybrid` | Model-family behaviours |
| `@gate` | Distribution Spread Gate |
| `@ui` | Decision Cockpit (Playwright) |
| `@copilot` | Live Gemini Copilot |
| `@knowledge` | Knowledge corpus, retrieval and citations (Epic H) |
| `@voice` | Voice Copilot through the Gemini Live API (F23) |

`BDD-n` = Feature n below. Feature IDs such as A4 or F13 refer to features.md.

## 2. Actors and Glossary

| Actor | Description |
|---|---|
| **Manager / shift lead** | Uses the **Decision** dashboard (Overview, Decisions) and the Demo Report |
| **Operator** | Uses the **Decision** dashboard (Quality, Decisions) and the Copilot |
| **Process / APC engineer** | Uses the **Technical** dashboard (Time-Series Explorer, Replay, Data Quality, Labs, What-if) |
| **Data scientist / model owner** | Uses the **Modelling** dashboard (Model Comparison & Parameters, Confidence, Calibration) |
| **Any user** | Uses the floating Gemini panel (text and voice) with cited source previews, on every dashboard |
| **Soft Sensor** | Model committee → mixture distribution |
| **Copilot** | Live Gemini ADK agent in the cockpit |
| **MPC / DCS** | The only component that actuates (none in the demo) |

| Term | Definition |
|---|---|
| Simulated run | One `run_sim.m` output: `batch_id` + `run_id`, one row per minute |
| Simulator truth | The true `LCO_T98_F` / `HN_T98_F` every minute; evaluation and labelled overlay only |
| Mixture | Weighted Gaussian mixture of admitted model distributions plus bias variance (SDD §5.7) |
| W90 | Width of the mixture's 90% interval (q95 − q05) |
| Spread gate | Withholds recommendations when W90 > limit or the mixture is bimodal (SDD §5.10) |
| Shadow model | Displayed but weight 0 (failed admission, SDD-MOD-07) |
| Knowledge corpus | 46 SIMULATED documents generated by Gemini (delegation.md), validated by `check_corpus.py` into `manifest.json` (SDD §7.9) |
| Citation | `[DOC-ID rN §x.y]`, resolving to a manifest document, revision and section (SDD-KNW-06) |
| Relevance threshold | 0.35; below it nothing is citable and the answer is labelled "No cited source" |

### BDD-15: Distribution Spread Gate `@gate` (NEW)

```gherkin
Feature: No recommendation when the probability distribution is too wide
  As an operations manager
  I want the system to hold back advice when it is not sure
  So that every recommendation it does make can be trusted

  Background:
    Given the spread limit w90_max is 14.0 °F for LCO_T98_F
    And the replay of a held-out simulated run from batch "full_v1"

  @gate @demo
  Scenario: Narrow distribution allows a recommendation

    When the recommendation engine runs
    Then a recommendation may be issued
    And gate status is PASS

  @gate @demo
  Scenario: Wide distribution withholds the recommendation
    Given the mixture W90 is 18.4 °F
    When the recommendation engine runs
    Then no actionable recommendation is issued
    And a WITHHELD record is written
    And the message reads "Distribution spread too wide — W90 = 18.4 °F exceeds limit 14.0 °F. No recommendation issued. Likely cause: inputs outside the training envelope. Suggested action: request a lab sample; hold current set point."

  @gate @demo
  Scenario: Models disagree (bimodal) withholds even when W90 is within the limit
    Given hybrid delta mean 752 °F (sd 2) with weight 0.5 and PINN mean 760 °F (sd 2) with weight 0.5
    When the gate is evaluated
    Then Ashman's D is about 4.0 and the mixture is bimodal
    And the gate status is WITHHELD with the cause "models disagree"

  @gate @demo
  Scenario: Gate hysteresis prevents flicker
    Given the gate is WITHHELD
    When W90 drops to 13.5 °F (above 0.9 × limit)
    Then the gate stays WITHHELD
    And the message begins "Distribution spread too wide — W90 = 13.5 °F has not yet stayed below 12.6 °F for 10 minutes."

    Then the gate returns to PASS and the transition is audited

  @gate @demo
  Scenario: Severe spread drives trust RED
    Given the mixture W90 is 22.0 °F (over 1.5 × limit)
    When the trust score and gate are evaluated
    Then signal S7 is severe and the trust level is RED

  @gate @demo
  Scenario: Heavy-crude transition triggers withholding on simulated data
    Given models trained without the heavy family
    When a held-out simulated run moves from API 25 to API 20
    Then at least 80% of minutes after the move are WITHHELD or RED
    And no RAISE recommendation is issued during them

  @gate @demo
  Scenario: Distributions are calibrated
    Given all held-out simulated minutes
    When coverage is measured against simulator truth
    Then the mixture 90% interval contains simulator truth in 85% to 95% of minutes
    And w90_max is set so that |error| is within R in at least 90% of PASS minutes
```

## 5. Simulated Data Used by Each `@demo` Scenario

Every `@demo` scenario gets its data from the simulator. None uses hand-made data (SDD-RAW-05).

| Scenario group | Simulated source | How it is used |
|---|---|---|
| Lab synthesis and alignment | `sim_octave/data/full_v1/random_s*.csv` (`lab_sample`, targets) | Lab generator, then alignment |
| Bad sensor data | Same runs, with faults injected into a copy of the tag | DQ checks |
| Set-point tracking, gain, yield sensitivity | Windows with `event_code = 5` | Estimation, REC-03, REC-04 |
| Unfamiliar crude / heavy transition | Runs where `dist_feed_API` < 22 held out | Novelty, gate, trust |
| Condenser fouling drift | Slow `dist_condenser_eff` decline in every `random` run | Drift Sentinel |
| Calibration, coverage | All held-out simulated minutes with truth | CAL, TRU-04 |
| Cockpit, Copilot | Replay of `random_s140` (held out) through the API | Playwright and Copilot golden set |
| Cockpit wiring before `full_v1` has rows | `sim_octave/data/frontend_sample_1h/*.csv` (legacy 108-column, read-only; temporary fallback only, no `@demo` scenario uses it) | Early cockpit shell |
| Job-record track, shift logs | `sim_octave/data/full_v1/random_s100…s109.csv` → `knowledge/inputs/events_sNNN.md` → SHIFT-S100…S109 (`sim_run`, `sim_window`) | BDD-17 time-axis placement |
| Knowledge & citations, voice | `knowledge/corpus/` (46 SIMULATED documents, Gemini-generated per delegation.md) plus the `random_s140` replay | BDD-17, BDD-18 |
| Sensor-fault reference | Copies of simulated `full_v1` runs with injected sensor faults; the PCA method is validated against the public ML-PSE FCCU dataset (github.com/ML-PSE/FCCU-Dataset, MIT); not stored locally — re-clone if needed | PCA novelty cross-check |

**Layout:** `tests/features/bdd_XX_*.feature` (copied from above) with step definitions in `tests/steps/` (pytest-bdd), and `cockpit/e2e/*.spec.ts` (Playwright) for the `@ui` scenarios.
